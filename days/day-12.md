使用模板：[`daily-note.md`](../templates/daily-note.md)

## 今日目标

- 运行一次最小工作流，并记录输出、人工复核点和失败情况。

## 学习记录

- 完成内容：
  - 跑通「筛查 → 验证 → 记录」最小工作流一次，用真实只读数据记录三个环节的输出与人工复核点。
- 证据链接：
  - [筛查脚本](../experiments/lifi_price_spread_watch.py)
  - LI.FI 报价 API `https://li.quest/v1/quote`（验证环节，需带查询参数，裸访问返回 400）
- 初始假设：day-09/10/11 设计的「筛查 → 验证 → 记录」能稳定产出可复查结果。
- 实际观察：工作流一次跑通，筛查未触发（spread `0.112%` < 阈值 `0.5%`），按设计跳过执行、仅做记录；为验证「验证环节」本身，另跑一次 quote 得到可成交字段。
- 关键结论：最小工作流可以稳定产出可复查结果，但有两个人工复核点不可自动化——`priceUSD` 估值 vs quote 可成交价的落差、以及 `executionDuration=0` 的失真。
- 明日行动：day-13 基于此工作流写出可证伪的策略假设。

## 工作流运行记录（真实只读，未签名未广播）

### 环节 1：筛查（跑价差脚本）

```bash
python3 experiments/lifi_price_spread_watch.py \
  --chain-a 8453 --chain-b 42161 \
  --token-a 0x0000000000000000000000000000000000000000 \
  --token-b 0x0000000000000000000000000000000000000000 \
  --threshold 0.5 --json-output /tmp/d12-spread.json
```

输出：

```
2026-08-18T13:52:54Z ETH: chain 8453=$1897.33 chain 42161=$1895.20 spread=0.112% threshold=0.5% ok
exit=0
```

- 结果：spread `0.112%` < 阈值 `0.5%`，**未触发**（exit 0）。
- 人工复核点：`priceUSD` 是 CoinGecko 估值，`0.112%` 不代表有可套利空间。

### 环节 2：验证（quote 可成交字段，演示）

因未触发本应跳过；为验证「验证环节」本身，另跑一次同链 quote：

```
tool: fly
toAmountMin: 1881854665  (≈1881.85 USDC / 1 ETH)
feeCosts: LIFI Fixed Fee 2500000000000000  (≈$2.50 等值)
executionDuration: 0
```

- 人工复核点 1：`toAmountMin` 才是滑点后保底到账，比 `toAmount` 更保守。
- 人工复核点 2：`executionDuration=0` 无区分力，不等于零秒成交（同 [EXP-2026-08-12-01](../experiments/EXP-2026-08-12-01.md)）。

### 环节 3：记录

- 按 day-10 的 7 字段 schema 落本记录：时间 `2026-08-18T13:52:54Z`、链 `8453→42161`、资产 `ETH(18)`、规模 `1 ETH`、路径 `同链 fly`、成本 `Fee ~$2.50`、失败原因 `价差 < 成本底价`。

## 失败情况

- 无硬失败；唯一"软失败"是筛查未触发导致验证环节被跳过，属预期行为（`exit 0` 语义正确）。

## 复盘备注

- 哪个判断被证据改变：以为"跑通脚本=工作流完成"，实际发现「人工复核点」才是工作流能不能产出真结论的关键——自动化的价差 ≠ 可执行的 Edge。
- 还缺哪一条证据：把三个环节串成一个脚本/命令链，减少人工拼接（可作为后续 Hermes 工作流优化项）。
