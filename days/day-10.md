- 初始假设：一次观察只要记够「时间、链、资产、规模、路径、成本、失败原因」七要素，就能被后续复查和对照。
- 实际观察：价差脚本的 JSON 已覆盖时间/链/资产/价差/阈值/触发，但缺少「路径」和「成本」——这两个必须由 T3（quote）补上，否则记录无法判断机会是否真的可执行。
- 关键结论：结构化记录的价值在「可对照」：同一资产多次采样才能看出价差漂移；缺时间戳或缺成本，记录就退化成无法复查的备注。
- 明日行动：day-11 把机会字段固化成「输入 + 阈值 + 输出」的重复查询。

## 机会证据表 schema（7 字段 + 状态）

| 字段 | 说明 | 真实示例 |
| --- | --- | --- |
| `时间戳` | 采样 UTC，不可省 | `2026-08-18T13:52:54Z` |
| `链` | from/to `chainId` | `8453 → 42161` |
| `资产` | token 地址 + symbol + decimals | `ETH 0x0…0 (18)` |
| `规模` | `fromAmount`（含 decimals） | `1 ETH = 1e18` |
| `路径` | tool / route（bridge / swap / 多步） | `fly`（同链 swap） |
| `成本` | Gas + Fee + 桥费 + 滑点 | `Fee $2.50`、Gas `$0.02`、滑点由 `toAmountMin` 体现 |
| `失败原因` | 无信号 / 滑点过大 / 跨链超时 / 价差<成本底价 | `价差 0.112% < 成本底价，Edge 为负` |

**状态标注**（复用仓库全局约定）：`研究` / `模拟` / `纸面交易` / `真实执行`，防止把推测误写成执行结果。

**机器可读形态**：脚本 `--json-output` 已落前 5 个字段；「路径」「成本」由 T3 quote 结果补入，最终合成一条完整机会记录。
